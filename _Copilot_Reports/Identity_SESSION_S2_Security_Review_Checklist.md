# SESSION S2 — security review checklist and evidence register

Version: 0.3.1 — 2026-09-29 — OPEN / review plan, not a PASS report
Applies to: [S2 BFF draft](Identity_SESSION_S2_BFF_Contract_Draft.md) and [propagation map](Identity_SESSION_S2_Propagation_Map.md). Owner-selected directions: Kimia BFF, rotating refresh, strict consumed-token family revocation and reauthentication, 900-second access token, 86400-second absolute Session cap. No runtime system or test result is asserted here.

| S-05 access-token revocation | Decide whether closing/revoking Session invalidates already issued access tokens immediately or only through their expiry (at most 900 seconds). | Resource-server validation model (self-contained token versus introspection/current-Session check), logout/reuse/password-change tests and explicit user-facing promise. Restricted administrative recovery uses its separate operator MFA/permit contract, not a Person Session. Business/finance capability owners classify their own sensitive operations; Identity does not grant their permissions. | Owner direction recorded; review open |

If Credential and Session use separate stores, an increment or event in one store alone is insufficient: require a durable guard, acknowledgment/serialization and fail-closed refresh while propagation is unresolved. ## Minimum executable verification after architecture approval

Use synthetic secrets and an identified code/database revision. Required fault points: before/after atomic token-family commit, response loss, duplicate predecessor, parallel BFF workers, parallel Identity workers, expiry boundary, logout race, password change race, key rotation and cleanup race. Assert no raw refresh/access token in logs, events, traces, metrics labels or browser storage. Record command, environment, observed outcomes and unresolved failures. These are specifications, not tests reported as run.

## Closure rule

Security reviewers and the owner record dispositions for S-01–S-10, including selected idle/access-revocation/password-change policies and operational owners, on one versioned Platform candidate. Update the proposed S2 contract and all affected Blueprint/schema surfaces consistently. Later runtime verification and deployment evidence remain separate gates. Until then SESSION is OPEN and no active nonrotation text is silently superseded.
