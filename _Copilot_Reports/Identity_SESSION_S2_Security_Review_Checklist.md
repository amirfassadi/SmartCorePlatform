# SESSION S2 — security review checklist and evidence register

Version: 0.1.0 — 2026-09-29 — OPEN / review plan, not a PASS report
Applies to: [S2 BFF draft](Identity_SESSION_S2_BFF_Contract_Draft.md) and [propagation map](Identity_SESSION_S2_Propagation_Map.md). Owner-selected directions: Kimia BFF, rotating refresh, strict consumed-token family revocation and reauthentication, 900-second access token, 86400-second absolute Session cap. No runtime system or test result is asserted here.

## Review decision ledger

| ID | Decision / proof needed | Candidate evidence and acceptance observation | Current state |
|---|---|---|---|
| S-01 BFF trust boundary | Confirm whether refresh secrets remain only in a server-controlled store and how Identity authenticates the BFF. Browser must receive only protected cookie/session state. | Kimia deployment diagram, client authentication and key-management design, actual login/refresh response handling, cookie domain/SameSite/Secure/HttpOnly and CSRF/XSS review. A name “BFF” is insufficient. | Open; owner direction only |
| S-02 multi-tab and multi-instance | Ensure one legitimate browser Session causes at most one in-flight presentation of a refresh generation across BFF workers. Observe one successor or strict family revocation, never two valid successors. | Open |
| S-03 lost response / forced logout | Quantify the cost of strict consumed-token reuse on weak networks. | Inject response loss after Identity commit and BFF restarts. Record forced-login rate per simulated refresh attempt, latency, concurrency and network-loss assumptions. Set an owner-approved usability threshold before release; do not invent an expected production rate. If threshold fails, revisit a separately reviewed secure recovery design. | Open; strict failure direction selected |

## Minimum executable verification after architecture approval

Use synthetic secrets and an identified code/database revision. Required fault points: before/after atomic token-family commit, response loss, duplicate predecessor, parallel BFF workers, parallel Identity workers, expiry boundary, logout race, password change race, key rotation and cleanup race. Assert no raw refresh/access token in logs, events, traces, metrics labels or browser storage. Record command, environment, observed outcomes and unresolved failures. These are specifications, not tests reported as run.

## Closure rule

Security reviewers and the owner record dispositions for S-01–S-10, including selected idle/access-revocation/password-change policies and operational owners, on one versioned Platform candidate. Update the proposed S2 contract and all affected Blueprint/schema surfaces consistently. Later runtime verification and deployment evidence remain separate gates. Until then SESSION is OPEN and no active nonrotation text is silently superseded.
